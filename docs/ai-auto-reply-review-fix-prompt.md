# AI 自动回复审查问题修复提示词

你正在维护一个 Spring Boot、MyBatis 与 Vue 3 项目。请直接修复以下已确认的代码审查问题，并运行相关测试。不要引入 Redis、MQ、新任务框架或新的业务状态机。

## 必须修复

1. 跨来源去重必须是一对一匹配。
   - 同一条平台消息不能同时吞并本地 AI 与本地后台消息。
   - 将 AI 和后台候选合并后，按相同内容和最近发送时间选择唯一候选。
   - 最近时间并列时保守地不合并。
   - 只有 `markDuplicate` 实际成功后才能写平台消息的 `reply_origin`。

2. 图片消息必须参与跨来源去重。
   - 平台文本/图片分别对应本地 AI 文本/图片与后台文本/图片。
   - 本地 `[图片]` 前缀和 HTTP/HTTPS URL 规范化不得阻止同一图片匹配。
   - 平台回流后的图片必须保留 AI 或 BACKEND 来源，不能误显示为 App 回复。

3. AI 时间线状态不能绕过真实消息分页。
   - 首次会话加载始终返回全部活动状态（等待、处理中）。
   - 失败和取消等终态状态只返回最近有限数量，避免历史记录无限进入轮询响应。
   - 不新增真实聊天消息，也不影响真实消息 offset。

4. AI 120 秒必须是底层 HTTP 请求的绝对超时。
   - 使用项目已有依赖实现整个请求的 call timeout，超时需取消底层网络调用。
   - 保持连接、读、写超时的合理配置。
   - 不要仅在业务线程外层等待或中断线程。

## 验证

- 增加或更新单元测试：AI/后台候选竞争、图片双来源去重、终态时间线限制、绝对 HTTP 超时配置。
- 运行 Maven 测试、前端类型检查与构建、`git diff --check`。
- 不修改无关业务行为；对真实平台 JSON 未覆盖的假设保持保守。
